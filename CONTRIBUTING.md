# Contributing to Zero Vault

<p align="center">
  <strong>Guidelines for Improving the Zero Vault Showcase</strong>
</p>

---

## 1. Introduction

Thank you for your interest in Zero Vault.

Zero Vault is a personal finance management project focused on financial visibility, transaction organization, and automation.

This public repository showcases the project's architecture, engineering decisions, documentation, and development progress.

Contributions that improve the clarity, accuracy, and presentation of the project are welcome.

---

## 2. Scope of Contributions

This repository is dedicated to public-facing project materials.

### Contributions Welcome

- Documentation improvements.
- Architecture diagram corrections.
- UI presentation suggestions.
- Documentation proofreading.
- Bug reports concerning publicly documented information.
- Feature suggestions.
- Accessibility and presentation improvements.

### Outside the Scope

The following are maintained privately:

- Core application source code.
- Internal development configuration.
- Private API credentials.
- Database files containing personal financial information.
- Unreleased implementation details.

Contributing to this repository does not grant access to the private implementation repository.

---

## 3. Before Contributing

Before submitting a contribution:

1. Review the existing documentation.
2. Check whether the issue has already been reported.
3. Ensure proposed changes do not expose sensitive information.
4. Keep contributions focused and relevant to the showcase.

For significant changes, open an issue first to discuss the proposed direction.

---

## 4. Reporting Issues

When reporting an issue, provide enough information to understand the problem.

A useful report includes:

- A clear title.
- A description of the issue.
- The affected documentation file.
- Expected behavior or content.
- Suggested corrections, if available.

Do not include credentials, private financial records, or personal account information in issue reports.

---

## 5. Suggesting Features

Feature suggestions should explain:

- The problem being addressed.
- The proposed improvement.
- Its potential benefit.
- Any relevant limitations or considerations.

Suggestions involving external financial integrations should identify whether an official and authorized integration method is available.

---

## 6. Documentation Standards

Documentation contributions should follow these guidelines:

- Use clear and professional English.
- Use Markdown consistently.
- Keep sections focused on their stated purpose.
- Avoid repeating content across documentation files.
- Distinguish implemented functionality from planned functionality.
- Use diagrams when they improve technical understanding.
- Avoid unsupported performance or security claims.

Accuracy is more important than making the project appear more advanced than it is.

---

## 7. Pull Request Guidelines

A pull request should:

1. Explain the proposed changes.
2. Identify affected files.
3. Describe why the changes are useful.
4. Include updated diagrams or screenshots when relevant.
5. Confirm that no confidential information has been introduced.

Keep each pull request focused on a single logical improvement.

---

## 8. Security Requirements

Never submit:

- API keys.
- OAuth tokens.
- Passwords.
- Real bank statements.
- Credit card information.
- Personal transaction histories.
- Private source code.
- Confidential configuration files.

If sensitive information is accidentally exposed, report it privately rather than reproducing it in a public issue.

---

## 9. Code of Conduct

Contributors are expected to maintain a respectful and constructive environment.

- Be respectful of different opinions.
- Provide useful technical feedback.
- Avoid personal attacks.
- Keep discussions relevant.
- Accept constructive criticism.

---

## 10. Contribution Philosophy

Zero Vault values contributions that improve engineering quality, transparency, and usability.

The objective is not simply to add more documentation or features, but to make the project easier to understand, evaluate, and improve.
